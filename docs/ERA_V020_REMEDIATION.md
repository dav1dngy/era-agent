## 2. Per finding

### H01 — final-state verification
*Root cause:* `verifyCurrent()` captured the changed-file list before build/test/acceptance commands ran and `evaluateChange()` judged that list; `finalize` computed a new patch afterwards and reused the old decision. Rebuild had the same ordering.
*Fix:* guards (protected paths, file count, diff size) are now `changeGuards()`, applied to the working copy after the commands; the decision carries the hash of the patch it judged; `finalize` re-applies the guards and rejects any state whose hash differs from the last verified one. Changes made by commands are reported as warnings.
*Behavior change:* a project whose tests write files now has those files in the diff and judged by the guards (they were always in the patch that would be applied).

### H02 — rollback manifest
*Root cause:* `treeDigest()` deliberately ignores `.git`, `build`, `dist`, `node_modules` and others, yet rollback used it to justify deleting the whole destination.
*Fix:* approval writes `destination-manifest.json` (every path, nothing excluded, symlinks not followed; SHA-256 per file). Rollback deletes only if the destination equals it; otherwise it names the added, removed or modified paths and deletes nothing. Runs approved before manifests existed refuse when excluded directories hold content.

### H03 — exposure per invocation
*Root cause:* the filter ran only when the working copy was made; role snapshots were unfiltered.
*Fix:* `enforceInvocationExposure()` runs before every agent invocation on the directory that agent sees (live copy or snapshot): withheld files are removed from that view, secret-looking content stops the run before the agent starts, snapshots are filtered at creation, and each invocation is recorded in `run.exposure_invocations` and the report. Only agents that are remote or read instruction files are affected.

### H04 — Git panel
*Fix:* `git` runs with a rebuilt environment (no secrets, private HOME, no system/user config, no pager/ssh/askpass), inside the sandbox (no network, no writes, reads limited to the repository). Without a sandbox, repositories whose config or attributes can execute programs (`hasExecutableGitConfig`) are refused unless Trusted execution is enabled.

### H05 — sandbox
*Fix (macOS profiles in `src/safety/sandbox.js` and `candidate-sandbox.js`):* `(deny signal)` except self and same-sandbox; reads of the home directory, `/private/tmp` and the user temp directory denied, with the toolchains on `PATH`, the running Node, ERA's code, `~/.gitconfig`, the working copy and explicit inputs allowed back; Apple's `xcrun_db` cache allowed (git, make and clang need it). Trusted coding-agent CLIs (`keepEnv`) keep their previous read behavior.
*Note on protected paths:* `src/safety/` and `src/evaluation/` are protected from **automated** improvement cycles (see CLAUDE.md). These edits were made manually, on the user's instruction, as a security fix; they change how the Lab's evaluator sandboxes candidates (read allowances were added at four call sites). A real Improvement Lab cycle (propose, implement, evaluate with real REA) was run on the final code to confirm the Lab still works; see section 3.

### M01 / M02 / M03
M01: the URL parse moved inside the guarded block (400 for malformed targets). M02: terminals are re-checked on every input, on every settings change and every second, and a violation SIGKILLs the process group. M03: reads inside a denied directory can be reopened for the working copy, so the terminal can read and build its own copy while other state stays unreadable.

### M04 — CI
`ci.yml` gained a required macOS job (dependency lock, signatures, audit, renderer and dependency tests that **fail if any is skipped**, Electron scenarios, package build, packaged smoke). `release-validation.yml` builds the desktop archive, checksum and CycloneDX SBOM and attests the archive separately. *Not done:* a run on a hosted runner.

### M07 / L02 / L03
Offline documentation (first a bundled Help view, replaced in Phase 7 by a Documentation section that renders the repository's own pages from the control plane), native Help menu, palette keyboard containment and ARIA. For L03 Monaco 0.57.0 (latest) bundles DOMPurify 3.4.15 and the patched 3.4.16 cannot be applied by an override because the code is inside Monaco's built file. **Maintained exception, tied to the exact artifact:** `monaco-editor@0.57.0` with DOMPurify 3.4.15; GHSA-p98j-92pf-mc4p and GHSA-6688-9rhm-gjv2; not reachable because both need `IN_PLACE` mode which Monaco never requests (test), untrusted hover Markdown is sanitized in the real renderer (desktop scenario) and the CSP forbids inline script (test). `tests/studio-dependencies.test.js` fails when Monaco or the bundled DOMPurify changes (re-evaluate) and when a patched DOMPurify ships (remove the exception). Review when Monaco releases.

## 5. Not verified, accepted limitations and remaining release blockers

**Not verified (UNVERIFIED):** a hosted CI run of the new job; Claude Code against the real CLI and a real `claude+codex` team; any new real provider generation (none was requested or run); Windows and Linux Studio; signing, notarization and Gatekeeper acceptance; installation on a clean machine; a screen-reader pass; independent re-review of these fixes.

**Accepted limitations (documented in the user-facing security pages):**
* The sandbox is macOS-only and built on the deprecated `sandbox-exec`. Reads outside the home directory and shared temp folders (for example external volumes) remain open; coding-agent CLIs run under their own isolation and can read whatever the account can. On Linux there is no ERA sandbox: project commands need Trusted execution, and Git inspection of repositories with executable configuration is refused.
* Terminal revocation kills the process group; a process that deliberately starts its own session escapes it.
* Exposure sweeps skip `.git` and `node_modules`; secret-content scanning skips generated directories (`build`, `dist`, …) as before. Files that verification commands create *after* the last agent run are not removed and appear in the diff that approval applies (they are what the project's own commands produce).
* The Lab still cannot evaluate `apps/studio/` code (its self-analysis covers the packed CLI) and requires a branch named `main`.
* Approval is a local acknowledgement, not an authenticated identity; there is no SSO or RBAC.

**Remaining release blockers (nothing here is claimed done):**
1. Independent re-review of H01-H05 (a second reviewer should try to bypass the new checks).
2. A green hosted CI run of the desktop job, then a desktop archive with provenance.
3. Developer ID signing and notarization if a distributed macOS app is intended; otherwise state "unsigned development build" wherever it is offered.
4. Real-provider validation with explicit authorization: Claude Code sign-in and a `claude+codex` run, and a cost-cap check with a metered agent.
5. Clean-machine installation test of the documented routes, the five remaining screenshots, and an accessibility pass.
6. Publish the remediation commits (the remote `feature/era-v0.2.0` branch is still at `52dcf82`, so a fresh clone does not contain them), which requires an explicit decision.
